## Decisions

- The CI failure was main's, inherited through the merge ref (#71 changed roles/routing without sync or tests). Fixed on this branch in two labelled commits (`e0f5ed5`, `6b38be2`) so the PR check could go green; both land on main with the PR.
- `outcome` is derived from seat exits because `dispatch.sh` writes `aborted` from its exit trap for both operator stops and self-ending failures. Rule: all seats exited and one not success = failed; a seat still in flight at close-out = aborted.
- `last_event_age_s` removed rather than kept beside the timestamp: leaving it invites the page to keep using the frozen number the critic flagged. Both renderers guard the clause, so it drops silently until the page half reads `last_event_ts`.
- Secret patterns copied into the reader (not imported from `experience_data.py`): the reader sits in the launcher pipe and must stay light and never fail. Same precedent as `desk_live.py`.
- Eight-token cap documented, not raised.

## Do not repeat

- `make -k test` does not run later suites when an earlier one fails: the `test` target is one recipe. Run the individual suite script instead.
- The commit-msg hook matches the substring `Generated with`, so "Regenerated with" is rejected.
- zsh: `${PIPESTATUS[0]}` is `${pipestatus[1]}`; capture exit codes with a redirect and `$?` instead.
