## Decisions
- **Channel value is `assistant`, because W0 has not settled one.** PR #2802 (W0 contract) is open and unmerged; the page settles a service directory name (`services/iris`, itself PROPOSED) and nowhere names a channel enum value or a `source` value. Stated in the PR body. Cheap to change while the migration is unapplied.
- **Kept the `NOT VALID` + `VALIDATE` two-step from `000033` rather than inventing a third pattern.** #1912 is open and settled on "move the VALIDATEs to their own migration, or use NO TRANSACTION deliberately, when the chat tables pass ~1M rows or before public launch". Neither trigger has fired. Widening a CHECK makes the new predicate a strict superset of the old, so the VALIDATE scan cannot fail.
- **The down re-adds the narrow constraints as validated, not NOT VALID.** A rollback on a database holding `assistant` rows then stops with 23514 instead of quietly admitting rows its own CHECK forbids. Proven; see Evidence.
- **`UpdateResultSessionFields` left untouched.** The column is the migration, the stale-writer predicate is W2 (#2800). The generated SQL text still ends `WHERE id = $6 AND deleted_at IS NULL`.
- Constraint name `channel_bindings_channel_check` was read from `pg_constraint` on a live database, not assumed from the `<table>_<column>_check` pattern.

## Do not repeat
- Do not add the revision predicate to `UpdateResultSessionFields` in this PR. It is W2 and the PR body says so.
- Do not "fix" the one-active-binding index here. With a single `assistant` channel value, `idx_channel_bindings_active_user_channel` lets a traveller hold exactly one live assistant binding in total, so connecting host B revokes host A. That contradicts D4's two-hosts-at-once pilot. The PR body states it and names two candidate shapes (host discriminator column in the index, preferred; or per-host channel values). The choice belongs with the authorization-server work in the same wave.
- Do not rename or edit `000033`. The widening is done by DROP + ADD in the new file.
- `make check-migration-filenames` needs `GITHUB_REPOSITORY` set locally or it exits 2 before doing any work. That is a local-only wrinkle; in Actions the var is always present.
- The local dev database (`olympus-postgres` container) is left migrated to `20260911080505`. Run `make migrate-down` there before going back to a branch without this file.
